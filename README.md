# 中小事業者のための情報セキュリティーマネジメント

**経営者のための情報セキュリティー入門**に記載した「AIを活用した情報の簡易棚卸し」ツールです。  

情報の簡易棚卸し=>セキュリティ対策は以下の流れを想定しています。  
(1) 情報資産・機器の棚卸し  
(2) CIAの評価  
(3) 情報資産に対する脅威・リスクの洗い出し  
(4) リスクに対する管理策の洗い出し   
(5) 実施する管理策（セキュリティ対策）の決定と実施   

これらのうち(3),(4)を行うには、ITの経験と知識、そして膨大な作業時間が必要でした。  
このツールの目的は、生成AIを活用してその作業負荷を軽減することです。
  
  
ここにある資料とリソースは、情報セキュリティーの維持改善にリソースを割くことが難しい、主として中小事業者様を支援するために[イー・レンジャー株式会社](https://www.eranger.co.jp)より無償提供されます。

## 利用するAIについて

Excelファイルの読み取り・作成ができるAIを使用します。  
会社紹介ページや機器の公開情報を調査するには、ウェブ閲覧機能も必要です。閲覧できない情報は未確認として扱います。
  
このツールはChatGPT 6.1で作成して・検証しています。
  
> [!IMPORTANT]
> **棚卸しリストをAIに添付・入力する前に、必ず以下を確認してください。**
>
> **個人向けプランでは、有料であっても、入力内容や添付ファイルがモデルの学習・再学習・改善に利用される場合があります。「有料だから学習に使われない」とは判断しないでください。** 個人向けと法人向けではデータの取扱いが異なる場合があるため、利用しているプランの規約と現在の設定を確認してください。
>
> - **会社が認めたAIを使用してください。** 入力情報の取扱い・学習利用・保存設定を確認してください。
> - **入力できる情報の範囲を確認してください。** 機密情報や個人情報は、会社のルールに従って除外・匿名化してください。
>
> **学習・再学習への利用は、次の順に確認してください。**
>
> 1. 利用しているAIのサービス名と契約プランを確認します。
> 2. **そのプランに適用される利用規約・データ取扱い方針**で、入力内容や添付ファイルがモデルの学習・再学習・改善に利用されるか確認します。
> 3. 学習利用を選択する設定がある場合は、現在の設定も確認します。
> 4. **利用されないことを確認できなければ、ファイルを添付・入力せず、利用を中止してください。** 必要に応じて会社の管理者やサービス提供者に確認します。
>
> 利用者は、所属組織の規程、適用法令、守秘義務および利用するAIサービスの契約・設定を確認し、**入力する権限のある情報のみを使用してください。**
>
> **本資料の安全確認指示は、入力情報の学習利用や漏洩を技術的に防止・保証するものではありません。** サービス側の設定を変更したり、送信済み情報の利用・保存・削除を保証したりするものでもありません。
  

## 情報の簡易棚卸し=>セキュリティ対策の流れ

| 段階 | 内容 |
| --- | --- |
| 1. 簡易棚卸しリスト（情報)の記入： | 守るべき情報と、そのCIAを整理します。必要に応じてsamples以下の記入例を参考にしてください。 |
| 2. 簡易棚卸しリスト（機器)の記入： | 情報機器の情報を記入します。必要に応じてsamples以下の記入例を参考にしてください。  |
| 3. 脅威・リスク・管理策のリスト作成 | AIに作成を依頼します。必要に応じてsamples以下の出力例を参考にしてください。 |
| 4. 脅威・リスク・管理策のリストを評価 | リストの各行について発生する可能性を評価します。 |
| 5. 管理策を決定する | 優先順位の高い行について管理策を決めます。 |

### 1. 簡易棚卸しリスト（情報)を記入する

「簡易棚卸しリスト（情報）.xlsx」に入力します。

- 情報の内容、媒体、保管場所、責任部門を記入します。社内に保管している情報だけでなく、ホームページ・オンラインショップ・クラウド上の情報も対象です。
- 同じ情報でも媒体や保管場所が異なれば別の行にし、No.は重複させません。委託先などは注記します。
- **CIAは情報資産ごとに1回評価します。** 

<details>
<summary>CIAの意味と選択肢を見る</summary>

| 項目 | ー | ◯ | ◎ |
| --- | --- | --- | --- |
| C：機密性 | 該当しない | 社内に影響 | 社外にも影響 |
| I：完全性 | 間違っていても業務に支障なし | 確認・手直しをして、影響を防げる | 確認・手直しが間に合わず、大きな影響が出る |
| A：可用性 | なくてもなんとかなる | 数日は無くても待てる | 数時間以内に復旧したい |

Cは許可のない人に情報が知られたとき、Iは情報が間違っていたとき、Aは情報が利用できなくなったときの影響を意味しています。

</details>

### 2. 簡易棚卸しリスト（機器)を記入する（任意）

設置している情報機器が分かれば「簡易棚卸しリスト（機器）.xlsx」に、種別・メーカー・型番・設置場所・責任部門・用途などを記入します。**このリストがなくても、次へ進めます。リストがある場合にはそれを加味して、脅威・リスク・管理策のリストを作成します。**

- UPS利用は「ー：利用なし」「◯：利用」から選びます。不明な欄は空欄で構いません。
- パソコンの台数は、個別の機器一覧と区別して集計表に入力します。
- ファームウェアやOSのバージョンを調べて入力する必要はありません。

<details>
<summary>機器リストが分析にどう使われるかを見る</summary>

機器リストがあれば、たとえばCAD用サーバーの復旧、共有ネットワーク機器の停止、UPSの保護範囲などを具体的に検討できます。ただし、情報と機器の対応が明記されていない場合、機器のリスクを情報資産のリスクに紐付けることはできません。

生成AIは、メーカー・型番が分かる機器は、メーカー公式情報やJVN等から既知の脆弱性・サポート状況を調査します。搭載バージョンや設定が不明な場合は影響を断定せず、保守業者への確認や更新要否の確認を管理策候補に含めます。古い機器やUPS利用なしという記載だけで、安全性や対策の十分性を決め付けません。

</details>

### 3. 脅威・リスク・管理策のリスト作成 

**プロンプトは書き換えません。また、簡易棚卸しリストは生成AIから添付を促された後に添付してください。**

1. プロンプトのテキストファイルを開き、全文をAIの入力欄にコピーします。「このプロンプトの指示にしたがって作業してください」と入力して送信します。会社の非公開情報は、まだ入力しません。
2. AIから利用条件を質問されたら、上記「利用するAIについて」に従って確認し、回答します。**学習に利用される場合や、利用されないことを確認できない場合は、ここで停止します。**
3. 確認が済んだら、下の会社情報（下記）をチャットで伝えます。分からない項目は「未指定」で構いません。
4. 簡易棚卸しリスト（情報）を添付します。簡易機器リスト（機器）があれば一緒に添付し、「この資料でExcelを作成してください」と送信します。

会社情報は、次をコピーして入力してください。

```text
会社紹介ページURL：
従業員数：
IT管理体制：
既存の管理策：
```

会社概要が未指定でも、生成AIは棚卸しリストから分かる範囲で結果を作成します。不明な内容は確認事項として残します。  


### 4. 脅威・リスク・管理策のリストを評価 

生成AIが作成したExcelをダウンロードして「脅威・リスク評価」シートを開き、次を確認します。

- 元の情報やCIAが維持されているか。
- 脅威・リスクが自社の実情に合っているか。関連候補の機器や委託先の前提が正しいか。
- 管理策候補が実行できる内容か。不明点を担当者・委託先・保守業者に確認できるか。

**管理策候補まで、この時点で作成されています。** 「発生の可能性」は空欄です。

<details>
<summary>脅威の分類・シート構成・各列の説明を見る</summary>

分析の単位は管理棚卸しリスト（情報）の1行です。各情報資産について、次の6分類ごとに2件ずつ、計12件の脅威・リスクを整理します。

| 脅威分類 | 主な観点 |
| --- | --- |
| 物理的 | 盗難、破損、持ち出し |
| 環境・災害 | 火災、浸水、地震、停電 |
| 人的・偶発的 | 誤入力、誤削除、取り違え |
| 人的・意図的 | 内部不正、改ざん、情報の持ち出し |
| 技術・サービス障害 | 機器故障、通信・クラウドの障害 |
| サイバー攻撃 | 不正アクセス、ランサムウェア、サービス妨害 |

この6分類は洗い出しのための実務上の分類であり、ISO/IEC 27001が定めた脅威の固定分類ではありません。機器ごとにさらに12行を作るのではなく、情報資産の分析に機器情報を反映します。


**出力の構成**

| シート | 内容 |
| --- | --- |
| 脅威・リスク評価 | 先頭に表示する分析表。評価入力とスコア計算、管理策候補をまとめます。 |
| 元の情報棚卸しシート | 元データとCIAの入力元を保持します。 |
| 元の機器棚卸しシート | 添付されている場合に、個別一覧・台数集計を保持します。 |
| 会社概要 | 確認できた会社情報、情報源、未確認事項をまとめます。 |
| 機器調査・確認事項 | 機器の公開情報調査や対応関係の確認事項を記載する場合に作成します。 |

「脅威・リスク評価」には、元の情報リストの列を保持したうえで、右側に次の列を追加します。

**脅威分類 → 脅威（脆弱性） → リスク → 情報－媒体－保管場所１ → 発生の可能性 → リスクスコア（目安） → 管理策候補**

- リスク欄は薄緑、発生の可能性の入力欄は淡い黄色です。
- 「発生の可能性」の直前に「情報・媒体・保管場所」を再表示し、横に移動しても対象を確認できるようにしています。（適宜、見出し行の固定などを行なってください）
- CIAは出力Excel内の元の情報棚卸しシートを参照し、同じ資産の12行（脅威分類6個に対して各2個）に共通して反映します。変更するときは、出力Excel内の元の情報棚卸しシートで修正します。
- 管理策候補は、各行の1セルにコンマ区切りで記載します。管理策作成のために別フェーズへ進む操作は不要です。

元データ・CIAが維持されているか、機器の対応や前提が正しいか、提案が自社で実行できる内容かを確認してください。  
脆弱性情報には対象条件・参照URL・確認日があること、設置機器への影響が未確認の場合はその旨が区別されていることも確認します。

</details>

### 5. セキュリティ対策するリスクと管理策を決定する

**薄緑の「リスク」欄を読み、対象情報を確認して、淡い黄色の「発生の可能性」欄を選択します。** 同じ情報資産でも、リスクごとに評価してください。

| 選択肢 | 点数 |
| --- | ---: |
| ー：ほぼなし | 0 |
| ◯：ありそう | 1 |
| ◎：大いに心配 | 2 |

**スコアは検討する順番の目安です。0でも「リスクが存在しない」という意味ではありません。** 点数だけで対応の要否を決めず、最終的な判断は経営者・業務責任者が行います。

対策する事項を決定したら、担当者や委託先・保守業者と管理策を確認して対策を実施します。  
管理策の選定には、担当者・期限・費用・実施後に残るリスク（残存リスク）といったファクターを加味します。  


<details>
<summary>スコアの計算方法と未入力時の扱いを見る</summary>

C・I・Aもそれぞれ、ー＝0、◯＝1、◎＝2として扱います。

**リスクスコア（目安）＝ 発生の可能性の点数 × CIAの点数の最大値**

計算結果は0・1・2・4です。簡易評価のため、その脅威がC・I・Aのどれに影響するかによらず、情報資産のCIAの最大値を使います。

- 発生の可能性が未入力なら、スコアも空欄です。
- 発生の可能性が「ー：ほぼなし」なら、CIA未入力でも0です。
- 発生の可能性が◯・◎で、CIAのいずれかが未入力なら、スコアも空欄です。
- 想定外の値は0に置き換えず、「要確認」等で示します。

スコアは対策を検討する順番の目安であり、ISO/IEC 27001所定の計算方法やリスク受容基準ではありません。0はリスクが存在しないという意味ではありません。点数だけで対応の要否を決めず、重大性・優先順位・管理策の採否・残るリスクの受容は経営者・業務責任者が判断します。

</details>
